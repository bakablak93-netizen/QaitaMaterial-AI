# QaitaMaterial AI — новый сайт v0.2 (HTML/CSS + React + FastAPI)

Это **сайт промышленной платформы**, а не презентация. Интерфейс полностью переработан на HTML-разметке (React TSX), современном CSS и TypeScript. Сервер остаётся Python FastAPI: он нужен для API, SQLite, безопасного хранения ключа, ML и LLM. Если заменить backend статическим HTML-файлом, регистрация, база данных и ИИ перестанут работать, поэтому **backend не удалён**.

## Что осталось работать из v0.1

- Регистрация, вход, выход, JWT; две роли при регистрации: производитель и покупатель.
- Данные SQLite сохраняются после перезапуска.
- Добавление, поиск, просмотр, редактирование через PATCH и удаление своих материалов, если нет связанных заявок.
- AI Material Analyzer: действительный серверный TF-IDF/cosine similarity, проверка недостающих данных и предупреждения о фосфогипсе. Это **не подтверждение промышленной пригодности**.
- Marketplace: материалы других предприятий, отправка B2B-запросов, просмотр заявок.
- Калькулятор экономики через рабочий серверный `/api/economy` с формулой и введёнными пользователем допущениями.
- Qaita AI Assistant: реальная OpenAI-совместимая интеграция через backend `.env` (работает **только с действующим ключом**).
- Dashboard: данные из SQLite, диаграмма по категориям, приведение kg к t.
- Три языка: қазақша / русский / English, переключение светлой и тёмной темы, сохранение настроек в браузере, адаптивность.

### Дополнительно в v0.2

- Новый дизайн панелей, боковой и мобильной навигации, карточек, модальных окон, форм, AI-результатов и чата.
- В интерфейс добавлены редактирование материала и экономический калькулятор (API уже существовал в v0.1).
- Получение и очистка истории AI-чата через `/api/ai/history` (только для авторизованного пользователя).
- Сценарные величины и синтетические данные отмечаются отдельно. Нет ложной имитации AI-ответов.

## Как обновить старую версию и не потерять данные

Это **новая папка проекта**, а не автоматический патч к уже запущенному приложению. Перед изменениями сделайте резервную копию прежнего проекта. Если вы уже пользовались v0.1, остановите старый backend и перенесите из старой папки в новую:

- `backend/qaitamaterial.db` — прежняя локальная база SQLite с пользователями, материалами, B2B-заявками и чатом;
- `backend/.env` — настройки подключения, JWT-секрет и ваш LLM API-ключ (не передавайте этот файл другим).

Заменять файлы старой базы или `.env` демоданными не нужно. В версии v0.2 структура существующих таблиц не менялась. Запускайте seed только если нужна дополнительная синтетическая выборка; команда idempotent и не должна дублировать исходные три демозаписи.

## Установка на Windows в VS Code

Нужны **Python 3.11+** и **Node.js 20+**.

**Терминал 1 — backend:**

```powershell
cd backend
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
Copy-Item .env.example .env
# Откройте backend/.env и установите свой JWT_SECRET_KEY и, по желанию, LLM_API_KEY
python -m app.seed
python -m uvicorn app.main:app --reload --port 8000
```

Если Python 3.11 отсутствует, используйте подходящий установленный Python 3.12/3.13 и замените `py -3.11` на его команду. Не оставляйте `JWT_SECRET_KEY` по умолчанию.

**Терминал 2 — frontend (из корневой папки проекта):**

```powershell
cd frontend
npm install
npm run dev
```

Откройте **http://localhost:5173/**; документация API — **http://localhost:8000/docs**.

Для повторного запуска активируйте существующий `.venv`, запустите uvicorn; затем `cd frontend` и `npm run dev`. Не нужно заново выполнять `npm install`, `pip install` или `seed`.

### AI-ключ

Откройте **backend/.env**:

```env
LLM_PROVIDER=openai
LLM_API_KEY=PASTE_YOUR_AI_API_KEY_HERE
LLM_MODEL=gpt-4.1-mini
LLM_BASE_URL=
AI_ENABLED=true
```

`LLM_BASE_URL` может быть пустым для OpenAI либо адресом доверенного OpenAI-совместимого провайдера. Укажите модель, доступную по вашему ключу. **Ключ не вставляйте в frontend, чат или GitHub.** Если ключ не задан, UI покажет «AI API не настроен»; анализ TF-IDF и калькулятор при этом продолжают работать.

### Проверка

```powershell
cd backend
python -m pytest -q
```

```powershell
cd frontend
npm run build
```

В окружении, где собирался архив, **6 backend-тестов пройдены**. Сборку React здесь не удалось подтвердить, потому что установка npm-пакетов блокировалась отсутствием доступа к registry.npmjs.org. Код TSX проверен на синтаксические ошибки компилятором TypeScript; полная сборка и визуальные e2e-тесты нуждаются в запуске на вашем ПК.

### Тестирование с двумя компаниями

1. Зарегистрируйте пользователя-производителя в компании A, добавьте материал.
2. Зарегистрируйте пользователя-покупателя в **другой** компании B.
3. Войдите от B: карточка материала A появится в Marketplace. Отправьте запрос.
4. Войдите от A: запрос отобразится в списке; материал с действующим запросом удалить нельзя (это защита целостности базы).
5. Откройте Analyzer и Economy, задайте реальные параметры сценария (в демо можно использовать условные значения с пометкой).

Пока нет полноценного workflow одобрения B2B-заявок, файловых вложений и документов, ML-прогноза накопления отходов, PDF/CSV-отчётов, Alembic-миграций, расширенной админ-панели, промышленной валидации и готовой защищённой production-конфигурации. Не выставляйте проект в открытый интернет без проверки прав доступа, аудита, ограничения частоты запросов и управления секретами.

Пример **«Казфосфат»** — это не подтверждение сотрудничества или внедрения. Синтетические примеры не являются реальными данными предприятия. ИИ не определяет самостоятельно законность или безопасность использования отходов.
